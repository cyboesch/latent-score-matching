Date: 2026-05-22

This report summarizes the widened all-digit, `28 x 28` MNIST experiment in [`notebooks/hybrid_mnist10_fullres_sweep_jax.ipynb`](../notebooks/hybrid_mnist10_fullres_sweep_jax.ipynb). The notebook was generated by [`notebooks/_build_hybrid_mnist10_fullres_sweep_jax.py`](../notebooks/_build_hybrid_mnist10_fullres_sweep_jax.py) and executed successfully with JAX on `CudaDevice(id=0)`. The notebook also saved its primary sample/prototype artifact at [`notebooks/hybrid_mnist10_fullres_sweep_outputs.npz`](../notebooks/hybrid_mnist10_fullres_sweep_outputs.npz).

## Why The Old All-Digit Run Failed

The `0/1` experiment is much easier than full MNIST-10. With `K=128`, the global DenseAM term has only about 12 or 13 prototypes per digit if the model is asked to cover all ten classes. At full `28 x 28` resolution, that is too little global capacity, and the local convolutional Bernoulli units do not by themselves enforce whole-digit geometry. They learn stroke-like local statistics, but not enough global topology to keep a sample on one coherent digit manifold.

So the failure was not just a bad random seed. The old search was under-scaled in three ways:

- too few global prototypes for ten classes;
- no explicit class-balanced prototype allocation;
- model selection was too tied to held-out DSM loss, which does not necessarily select the best sampler.

## What Changed

The new notebook keeps the same conservative hybrid score but widens the search around the actual MNIST-10 problem:

```text
score(x,t) = -x / sigma_t^2 + b + score_conv(x) + lambda * alpha_t / sigma_t^2 * sum_a r_a(x,t) c_a
```

where `r_a` is the softmax responsibility of DenseAM prototype `c_a`. The convolutional term remains the local hidden-Bernoulli free-energy contribution, while DenseAM supplies a global categorical latent variable.

The widened sweep uses:

- full `28 x 28` MNIST;
- all digits `0..9`;
- balanced train and validation subsets, `1000` train examples per class and `200` validation examples per class;
- `48` sweep configurations;
- `K = 500, 1000, 1500` prototypes, i.e. `50`, `100`, or `150` prototypes per digit;
- class-balanced random and class-balanced per-class MiniBatchKMeans prototype initialization;
- `lambda` values from `0.20` to `0.65`;
- `64` and `96` convolutional hidden channels;
- trainable DenseAM prototypes and frozen DenseAM prototypes;
- final retraining for multiple candidate winners, not just the lowest validation loss.

The notebook also adds a DenseAM-freeze switch:

```python
grad_dense = 0 if cfg["train_dense"] is False else grad_dense
```

That is important because it separates two regimes:

- **trainable DenseAM**: less direct memorization, but samples can be blurrier or class-skewed;
- **frozen DenseAM**: much crisper samples, but often prototype retrieval.

This is the least memory-like of the final candidates. The large `sample->proto` distance means it is not just snapping onto the global memory bank. The downside is class imbalance after the longer retrain, especially overproduction of `1` and underproduction of `8` and `9`.

### `best_frozen`

```text
K=1500, lambda=0.50, init=balanced_random, hidden_ch=64, train_dense=False
final val=91.278
sample->train=2.694
sample->sample=12.602
```

This gives the crispest-looking outputs in the saved artifact, but the metric tells the story: `sample->proto` and `sample->train` are both around `2.7`, far below the train-control distance of `11.62`. That is strong evidence of prototype retrieval. It is useful as an upper bound on visual quality, not as evidence that the local conv free-energy model has learned a non-memorizing MNIST generator.

## Interpretation

The full MNIST-10 result is not simply solved by making the old sweep wider. The model has two qualitatively different ways to improve:

1. Use strong frozen DenseAM memory. This produces crisp digits, but mostly by retrieving prototype-like examples.
2. Train the global prototypes and conv filters jointly. This is less memory-like, but the samples are less crisp and mode balance can drift.

The local convolutional hidden units do help: the best trainable-DenseAM configs are not nearest-prototype retrieval, and their `sample->proto` distances are large. But the conv hidden units are still not enough to carry full MNIST-10 global geometry alone. The global categorical latent variable is doing essential work.

## Practical Recommendation

For all digits, use the widened notebook rather than the old `K<=128` settings. A reasonable starting point is:

```python
K = 1500
lambda = 0.30
init = "balanced_random"
hidden_ch = 96
kernel = 5
train_dense = True
```

Use the frozen DenseAM setting only when you explicitly want a crisp retrieval-like baseline:

```python
K = 1500
lambda = 0.50
init = "balanced_random"
hidden_ch = 64
kernel = 5
train_dense = False
```

The next real modeling improvement should be one of these:

- add a time-dependent global weight `lambda(t)` so DenseAM shapes global structure at high/intermediate noise without forcing low-noise retrieval;
- add class-conditioned sampling by masking DenseAM prototypes to a chosen digit class during reverse diffusion;
- add a second coarse global latent layer, e.g. low-resolution prototypes plus local conv units;
- add homeostatic/class-prior regularization for DenseAM biases to prevent mode drift during long retrains.

Hyperparameter search improves the full MNIST-10 notebook, but the deeper lesson is that visual quality and non-memorization pull in different directions for this architecture.
